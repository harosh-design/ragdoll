# Архитектура и сравнение с аналогами

## Текущая структура

`main.js` связывает фазы матча, ввод, часы симуляции и отрисовку. `Game` содержит правила розыгрыша и счёт, не зависит от DOM. `world.js`, `player.js`, `spike.js` и `hazards.js` строят физические тела и обрабатывают столкновения. `bot.js` управляет вторым игроком через те же действия, что доступны человеку. `ui.js` отвечает за меню; `renderer.js`, `characters.js` и `scenery.js` — за Canvas. Параметры оригинальной игры собраны в `original.js`.

Сильная сторона проекта — физические правила уже можно проверять без браузера. При этом адаптер физических тел для Canvas и накопитель фиксированных кадров находились внутри `main.js`, а параметры из сохранения или файла попадали в физику без проверки диапазонов.

## Аналоги и выводы

| Игра / источник | Наблюдение | Вывод для проекта |
| --- | --- | --- |

| [Volley Random](https://www.twoplayergames.org/game/volley-random) | Короткие матчи до пяти очков, простое управление и вариации физики между раундами. | Важны быстрый рестарт, отзывчивый ввод и ясное состояние розыгрыша. Копировать случайную физику не требуется: здесь цель — воспроизвести физику оригинала. |
| [Box2D: Simulation](https://box2d.org/documentation/md_simulation.html) | Для устойчивой симуляции рекомендован фиксированный шаг. | Шаг физики должен оставаться независимым от частоты кадров экрана; накопленный после зависания долг следует ограничивать. |
| [Planck.js: user data](https://piqnt.com/planck.js/docs/api-conventions/user-data.html) | Физическим телам и фикстурам можно назначать прикладные метки. | Касания следует определять по метке игрока, а не по коэффициенту трения. |

## Изменения после анализа

- `fixed-step.js` управляет накоплением времени и ограничивает догоняющие шаги после задержки вкладки. Возобновление начинает отсчёт без остатка старого кадра.
- `presentation.js` преобразует координаты физики для Canvas, интерполирует движение и кэширует неизменную геометрию тела. После переноса игроков к новой подаче снимок координат обновляется.
- `Game.ballTouchedPlayer()` использует `bodyType` и идентификатор игрока из `userData`. Изменения трения больше не ломают правило касаний.
- `settings-model.js` хранит диапазоны и нормализует значения из локального хранилища, пресетов и импорта. Интерфейс ползунков использует ту же схему.

Проверка: `npm test` и `npm run build`. Ограничение числа догоняющих шагов означает, что после длительного зависания симуляция пропускает накопленное время, чтобы управление оставалось отзывчивым.
